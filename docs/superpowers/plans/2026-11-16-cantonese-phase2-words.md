# Jiesuo 粵 Phase 2: Words and Grammar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** After the tone check, the learner learns Hong Kong Cantonese words and grammar every day. Each word is tracked for hearing, reading and typing. The app adds a Jyutping typing trainer, a Read screen for friends' messages, Search with word pages, a Map, and neural-voice audio built with exact Jyutping.

**Architecture:** The Python build (`jiesuo/yue/`) resolves word readings from rime-cantonese, CC-Canto, words.hk and HKCanCor. It orders words by spoken Hong Kong frequency with the greedy closure from `jiesuo/order.py`, attaches attested example sentences, and writes one JSON file per licence into `app/yue/data/`. The app adds pure, node-tested modules (`lexicon.js`, `course.js`, `speech.js`) and screens that register on `window.JyutScreens` the way phase 1 does. Azure Speech audio is generated by an incremental build script that the learner runs with their own key. Until it runs, the app falls back to safe audio.

**Tech Stack:** Python 3.12 (venv from phase 1), pytest. Vanilla JS UMD modules, `node --test`. Azure Speech REST (build time only), ffmpeg for MP3.

**Spec:** `docs/superpowers/specs/2026-11-14-cantonese-design.md`. Phase 2 is §10.2. Also read §3 (Stage 1, Main course), §4 (screens), §6 (correctness), §7 (state) and §8 (audio). Phase 1 plan for conventions: `docs/superpowers/plans/2026-11-14-cantonese-phase1-sounds.md`.

## Global Constraints

**Language and readings**
- Hong Kong Cantonese, Traditional characters, Jyutping only. No Mandarin, no pinyin and no Simplified forms anywhere in the UI.
- Reading rules (§6): when all sources agree, accept the reading. Otherwise HKCanCor majority, then a reviewed words.hk reading, then `data/yue/overrides.tsv`. A taught item with no resolved reading fails a test.
- Every authored example carries `source` (`tatoeba:<id>`, `wordshk:<entry id>`, `hkcancor:<file>#<n>`) or `"unchecked": true`. Unchecked items are shown and heard but never scheduled or drilled (learner's decision).
- Every hand-written Jyutping in content must equal the lexicon reading. The only exception is a recorded changed tone (`"changed": true` with the base reading).
- Formal-only forms never appear in a colloquial example unless it is marked `"formal": true`. These are the tokens 他 / 在 / 的 standing alone after segmentation, and the substring 沒有.

**Licences**
- One JSON file per licence:
  - `lexicon.json` and `course.json`: CC BY-SA 4.0. Rime is CC BY 4.0; CC-Canto, CC-CEDICT and HKCanCor counts are compatible with that.
  - `sentences.json`: Tatoeba, CC BY 2.0 FR, with author names.
  - `wordshk.json`: words.hk Non-Commercial Open Data Licence. It carries the notice, the disclaimer, the credits and a link to https://words.hk.
- From words.hk, ship only published entries (`已公開`). Only reviewed entries (`OK`) count as a source for checking.
- Never add a Co-Authored-By or Claude trailer to commits. This is the learner's standing rule and overrides any harness default.

**Audio**
- The Azure key is read only from the `AZURE_SPEECH_KEY` and `AZURE_SPEECH_REGION` environment variables. It is never written to a file, a log or a commit.
- SSML: `<phoneme alphabet="sapi" ph="nei 5 hou 2">你好</phoneme>`. Each syllable is followed by a space and its tone number, 1–6. Checked tones use 1, 3 and 6, exactly as our Jyutping does. Source: Microsoft Learn, "Speech phonetic alphabets", zh-HK section.
- Voices: `zh-HK-HiuMaanNeural` (female, the default) and `zh-HK-WanLungNeural` (male).
- Audio size: keep `app/yue/` under 150 MB.

**App**
- Storage keys start with `jiesuo-yue-`. The progress file keeps `lang: "yue"`, and its version moves to `v: 2`. A `v: 1` file still loads.
- Grammar and teaching text lives in data files, never in UI code. Keep explanations short and factual. Every grammar point cites the reviewed words.hk entry for its key word (`cite`), resolved at build time.
- Bump the shell cache in `app/yue/sw.js` (currently `jiesuo-yue-v7`) whenever a shell file changes. Add every new file to `FILES`.

**Testing**
- Tests:
  - `node --test tests/` runs all JS tests.
  - `.venv/Scripts/python -m pytest tests/ -k yue` runs the Cantonese Python tests.
  - The 34 Mandarin pytest failures are pre-existing (Mandarin data was never built on this machine). Leave them alone.
- The local preview runs from `.claude/launch.json` (name `jiesuo`), at `/yue/`.

## Review Focus

1. **A word whose characters have several readings, or a changed tone** (e.g. 名 meng2 in 個名, or 好 hou3 "to like"). The app must speak and show the word's own reading, never a per-character guess. Task 2 has the test, and Task 8 plays it.
2. **Pasting messy real chat into Read.** Pasted text may mix English ("佢 feed 緊"), emoji, Jyutping, Simplified characters or unknown characters. Expected: English and emoji pass through untouched, and unknown characters are shown with "not in the app yet". Read must never throw. The test is in Task 6.
3. **Typing Jyutping loosely.** Expected:
   - Upper case, missing tone numbers, spaces and "neihou" all give candidates.
   - Tones written 7, 8 or 9 map to 1, 3 and 6.
   - Invalid input gives "no match", not an error.

   The test is in Task 6.
4. **A progress file from phase 1 (`v: 1`, no `words`).** It must load without losing stage 0 progress. A corrupt `words` entry is refused as `bad-file`, never a silent reset. The test is in Task 7.
5. **No neural audio yet, and offline.** A hear exercise for a word with no clip and no device voice must still play correct tones: the Cantone syllables in sequence, or skip with a message. It must never use a wrong guess. The test is in Task 8.

### Task 2: Word lexicon (readings, frequency, meanings)

**Files:**
- Create: `jiesuo/yue/lexicon.py`
- Modify: `data/yue/overrides.tsv` (word rows allowed), `reports/yue_readings.md` (new "Words" section)
- Test: `tests/test_yue_lexicon.py`

**Interfaces:**
- Consumes: the Task 1 loaders, `readings.resolve_all`, and `sources.load_hkcancor`.
- Produces in `jiesuo/yue/lexicon.py`:
  - `@dataclass Word(form: str, jp: str, alt: list[str], status: str, freq: float, en: str, changed: list[int], wordshk_id: int | None)`
    - `status` is one of `agree | corpus | wordshk | override | unresolved`.
    - `changed` lists the 0-based syllable indexes whose tone differs from every reading of that character (變音).
  - `resolve_word(form, srcs) -> Word`, applying the §6 order:
    1. All available sources (rime words, CC-Canto, reviewed words.hk) agree.
    2. Otherwise, take the HKCanCor majority if at least 3 tokens.
    3. Otherwise, take the reviewed words.hk reading.
    4. Otherwise, take the override.
    5. Otherwise the status is `unresolved`.

    Single characters use `readings.json`'s resolution, not this function.
  - `split_heldout(hkcancor) -> (train, test)`: a fixed split by sentence index, where every 5th sentence is test (20%). Readings and frequencies use **only `train`**. `test` is kept for Task 13.
  - `build_lexicon(srcs) -> dict[str, Word]`:
    - Candidates are forms of 1–4 characters found in HKCanCor tokens, reviewed words.hk forms, or CC-Canto, where every character has a resolved character reading.
    - `freq` = HKCanCor token count + 0.5 × the count in the secondary corpus. The secondary corpus is words.hk reviewed example sentences plus colloquial Tatoeba yue, segmented by `segment`. These counts are used for counting only, never shipped as text.
    - `en` comes from CC-Canto first, then CC-CEDICT (`data/raw/cedict.json`, matched on the traditional form). words.hk English is not stored here; it ships in `wordshk.json` (Task 4).
  - `segment(text, lexicon_forms: set[str], maxlen=4) -> list[str]`: longest match first. Characters not in the lexicon come out as single tokens. Non-Han runs (Latin, digits, emoji, punctuation) come out as one token per run.
  - `SRCS` loader: `load_sources()` returns a dict with every source above, cached under `data/raw/yue/cache/` like phase 1.

### Task 3: Course order, Stage 1, grammar and attested examples

**Files:**
- Create: `jiesuo/yue/course.py`, `data/yue/content/stage1.json`, `data/yue/content/grammar.json`
- Test: `tests/test_yue_course.py`, and extend `tests/test_yue_content.py`

**Interfaces:**
- Consumes: `lexicon.build_lexicon`, `lexicon.segment`, `jiesuo.order.Model` and `greedy`, the Task 1 loaders.
- Produces in `jiesuo/yue/course.py`:
  - `order_words(lex: dict[str, Word], first: list[str], n=5000) -> list[str]`:
    1. Stage 1 forms come first, in content order.
    2. Then `greedy(Model(value={form: freq}, prereq={multi-char form: set(chars) that are words in lex}))`, with lookahead 0.
    3. Truncate to n.

    Characters that are not themselves words get no unit; they are introduced with the word (spec §3).
  - `colloquial(text, seg) -> bool`:
    - True if the text contains any marker in `佢 係 喺 嘅 咗 冇 唔 哋 啲 嚟 乜 咩 嘢 噉 嗰 睇 畀 俾 㗎 囉 喎 啦 喇 嘛`, and
    - `formal_hits(text, seg)` is empty.
  - `formal_hits(text, seg) -> list[str]`: the formal-only forms found, per Global Constraints.
  - `examples(lex, tatoeba, wordshk, hkcancor) -> list[dict]`:
    - Each example is `{id, text, jp, en, source, words}`.
    - `jp` is built per segmented token from the lexicon. A sentence with any `unresolved` token is dropped.
    - Tatoeba gives `id = "tatoeba:<id>"` with its author. words.hk published, reviewed examples give `wordshk:<entry>#<k>` with their own jyutping. HKCanCor sentences have no English, so they are kept only for listening (`en: null`).
    - When words.hk gives its own jyutping and it disagrees with the lexicon, keep words.hk's jyutping for that example. Record the disagreement in the report.
